entry no. 007

nothing phones home, except this

6 September 2026 · the shyn daybook

Homebrew prints a cask's caveats at the end of an install. So for a few days, the release that added telemetry to shyn finished by telling you, in our own words:

Everything shyn captures stays on your Mac. Nothing phones home.

The first sentence was true. The second had been false since the binary above it finished copying.

We found it by upgrading and reading the output, which is the only way anyone ever sees that surface. Grepping the README, the site and the manifest for the stale claim never reached it, because the cask template lives under packaging/. That is the shape of this whole entry: the code was careful and the prose was behind.

Why there is any telemetry at all

shyn breaks in ways we cannot predict. Every Mac is a different OS version, different silicon, a different set of permissions granted and denied. We cannot test for that spread, and almost nobody who hits a bug writes in. They just quit the app.

Beta is when that visibility is worth the most. It is also when a memory product has the least standing to ask for it, which is why the constraints below took longer to build than the feature did.

What had to be true first

One egress point. The capture agents and the CLI report to the daemon over the socket that was already there. The daemon is the only process that touches the network. Two senders would make the one audit that matters for this product — what actually leaves this machine — unanswerable, and an unanswerable audit is the same as a bad answer.

A closed list of event names. Twenty of them, in packages/daemon/src/analytics.ts. No code path accepts an interpolated name, because interpolated names are how content escapes.

Properties allow-listed by shape, not filtered by pattern. Numbers and booleans pass; they cannot carry content. Strings pass only if they are an enumerated value or a known debug field, and that field is then scrubbed. Anything unanticipated is dropped rather than sent. A deny-list has to anticipate every shape content can take, and being wrong once ships someone's document title.

Off means off now. Turning it off discards whatever is queued. The promise is “off”, not “off after one more batch”.

Nothing exists before you answer. No random id is minted and nothing is queued until the first-run dialog has been answered, and declining destroys the id rather than muting it. People upgrading from an older version get asked too. They installed under the previous promise, and sending without ever telling them is the version of this that would actually break trust.

The audit our own promise failed

The README, the dialog and shyn.day all said analytics never carries content or file paths. Generating real crash payloads instead of imagined ones found two ways that was untrue.

The first was JSON.parse, which embeds a snippet of what it parsed into its own error message:

Unexpected token 'S', "SHYN_POSTH"... is not valid JSON

Those are the opening characters of a file, verbatim. For a malformed note or a hand-edited config, that is content, and we were sending it.

The second was the path scrubber, which only knew about /Users and /home. A project living under /Volumes/<client>/ or /opt/ went through untouched, and directory names are content — client names and project names live there.

Now every absolute path collapses to [path] unless it is a runtime internal, and quoted spans of six characters or more are redacted, because quotes are how titles and parse snippets travel. Diagnostic value survives on purpose, with a test pinning it: ENOENT still arrives, so does readFileSync (node:fs:539:20). What is gone is only the part that identified you.

One detail worth admitting. The first version of that test asserted Node echoes the entire parsed text. It truncates to about ten characters, so the test's precondition was wrong while the scrubber was right. We fixed the test, not the code. The opposite mistake is the one that ships.

Counting what went stale

Five claims on the home page: the meta description, the structured data, the hero line, the lead of the vault section, and the vow itself. Three in the README. Two daybook entries. One cask.

Entry 001 and entry 002 got a dated note above the prose rather than an edit. They were true when they were published, and quietly rewriting them to agree with today would erase the record of what changed, which is a worse dishonesty than a stale sentence standing with a date next to it.

What we will not call it

The dialog ships with the toggle checked. Under GDPR a pre-ticked box is not consent, so calling this opt-in would be a claim our own interface does not support; calling it opt-out would imply we started sending before you saw the choice, which is false. So every surface says the same plain thing: you choose on first run. Describing the mechanism stays accurate whatever the default turns out to be later.

What did not move

Captured content still never leaves this machine. Not screen text, not transcripts, not notes, not what you searched for, not your file names, under any setting. The events go to PostHog, on their US host, and the twenty names in analytics.ts are the entire surface — thirty seconds of reading beats any assurance we could write here, this one included.

The sentence we most wanted to keep is gone from every surface we control. It stopped being true, and a good line is not worth more than that.
